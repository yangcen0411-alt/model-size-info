# 模型占用信息 · SketchUp 插件

版本：1.2.0（开发版）

[下载插件安装包（RBZ）](https://github.com/yangcen0411-alt/model-size-info/raw/refs/heads/main/downloads/model_size_info_v1.2.0.rbz) · [下载源码包](https://github.com/yangcen0411-alt/model-size-info/raw/refs/heads/main/downloads/model_size_info_v1.2.0_source.zip)

这是一个类似“图元信息”的独立浮动面板：选择群组或组件后，显示该组件定义单独保存为 SKP 文件的实际字节数，并换算为 KB、MB。没有选择时，显示整个模型上次保存的文件大小。可点击“测量当前模型”，通过临时副本测量包含未保存修改的当前版本。

**1.2.0 改为按需读取，并加快测量队列**：打开组件树时只读顶层，展开哪一项才读取哪一层。取消启动时对全部定义/实例建立全局索引；相同定义的子层级共享缓存。测量时取消每个定义之间固定的 80 毫秒间隔，改为有时间预算的小批量处理；结构和大小只向面板发送变化部分。

## 安装和打开

适用于 SketchUp 2022 及更新的桌面版；不适用于网页版。采用这些版本公开的 Ruby API 开发，尚未完成 SketchUp 界面内的实际验证。

1. 下载 `model_size_info_v1.2.0.rbz`，保留 `.rbz` 后缀，无需解压。
2. 在 SketchUp 中打开 **扩展程序管理器**，点击 **安装扩展程序**，选择这个文件。不同版本可能将管理器放在“窗口”或“扩展程序”菜单中。
3. 打开 **扩展程序 → 模型占用信息**。也可以在建模区域右键菜单中打开“模型占用信息”。
4. 选中一个群组或组件，等待片刻即可查看大小。

这是未经过 Extension Warehouse 签名的开发版。如果 SketchUp 要求批准该扩展，请在管理器中手动批准此插件。无需更改全部扩展的加载策略。

从旧版升级时，安装新版 RBZ 后重新启动 SketchUp。扩展管理器中的名称仍为“模型占用信息”，面板右下角版本应为 **v1.2.0**。

## 如何使用

| 操作 | 显示内容 |
| --- | --- |
| 选择一个群组或组件 | 它的独立 SKP 文件大小、实例名称、类型、当前层内部图元数、模型中的实例数 |
| 选择同一组件的多个实例 | 相同定义只测量并计算一次 |
| 多选不同组件 | 各定义的独立文件大小，按体积从大到小排列，并显示合计 |
| 点击空白处取消选择 | 整个模型的上次保存文件大小 |
| 切换“整个模型” | 保持当前选择，同时查看模型大小 |
| 切换“组件树” | 先读取顶层群组和组件；展开时再读取子层级 |
| 点击“测量当前模型” | 临时保存当前模型副本，测量包含未保存修改的大小 |
| 取消“自动测量选择” | 选择后只更新属性，需要点击按钮才导出测量 |
| 点击右上角刷新 | 清除缓存并刷新；小范围选择在自动模式下会重新测量 |

自动模式下，选择稳定约 0.6 秒后开始测量，最多自动测量 3 个不同定义。选择更多不同定义时，点击“测量选中定义”开始。大型组件的单次副本保存由 SketchUp 同步执行，可能需要短暂等待；“停止后续测量”取消尚未开始的任务。

## 使用组件树

1. 打开面板，点击 **组件树**，先显示顶层目录；不再等模型中的所有定义都读取完，也不会自动导出组件文件。
2. 点击左侧箭头，只读取该定义的下一层。未读取的项目标记“展开读取”；确认没有群组/组件子项后箭头消失。同一定义的另一个实例可以直接复用已读层级。
3. 点击 **测量已读取项**，只测量当前已发现的不同定义。**不展开子级也能测量父级的完整 SKP 体积**，其中已经包含嵌套内容；未发现的子定义不会被另行导出。
4. 需要完整目录时，点击 **读取全部层级**；读取完后点击 **测量全部定义**。顶部“已发现定义”只统计已经读取到的对象定义，不是模型所有保留定义的总数。
5. 每层默认按体积从大到小排列，也可以选择“名称”或“对象编号”（持久 ID）。测量过程中保持当前顺序，完成后再更新排序。每层一次显示 100 项，可点击“再显示”查看后续项目。
6. 点击名称，选择并缩放到对应对象。定位嵌套对象会打开父级编辑环境；父级锁定或 SketchUp 不允许进入时显示提示，保留锁定状态。
7. 点击 **停止后续测量** 可停止尚未开始的工作。未完成的层级可收起后再次展开继续读取；点击 **继续测量** 只测量剩余定义。失败项会单独标记，成功结果保留。测量期间展开未读取项会排队，在当前测量结束后读取。

树中包含隐藏和锁定对象；未使用的定义不会被遍历，也不单列面、线和图片。这些图元仍包含在所属群组/组件的完整文件大小里。

**父级大小已经包含子级内容，不能把各层数值相加。** 此功能显示各定义独立保存为 SKP 的体积，不是每个实例对原模型文件的增量贡献。

修改模型会清除测量缓存并重新扫描层级；点击右上角刷新也可重新扫描。切换文档或关闭面板会取消未完成的任务。

### 扫描速度与测量速度

1.1.1 启动时仍要读取全模型的定义和实例列表。1.2.0 取消这一步，使用当前层的 `Entities` 类型筛选，只取群组和组件；未展开的深层定义不会被查询，也不调用 `definition.instances`。主动点击“读取全部层级”才会继续递归。当前层本身特别密集时，宿主程序执行类型筛选仍可能需要时间。

目录条目和导出任务均按时间预算分批处理，并降低进度刷新的频率；打开未变化的组件树会复用目录。面板只接收结构和大小的变化部分，进度更新复用 ID 缓存，避免重复读取每个定义的原生属性。界面显示最近一层的读取耗时。

旧队列在每个定义之前等待 0.08 秒，3700 个定义的名义定时间隔合计约 296 秒。新版取消此逐项等待，每批最多处理 20 个定义，约 12 毫秒后让出事件循环，再调度下一批。这个时间预算无法中断单次同步 SKP 保存。

**“读取目录”和“测量文件体积”是两个步骤。** 测量仍将完整组件（包括面、线、材质和嵌套内容）保存为临时 SKP。单次保存由 SketchUp 同步执行，仍可能等待，不能中途停止。尚未用用户的实际大模型进行性能计时，不承诺全部读取/导出的固定耗时。

## 大小的含义

- **群组和组件**：通过官方 `ComponentDefinition#save_copy` 将定义临时保存成当前 SketchUp 格式的 SKP，再读取实际文件字节数。包含定义中的几何、嵌套对象、材质和相关数据。实例外层的材质、缩放等覆盖不在组件定义中，因此不计入该数值。
- **同一组件多次复制**：实例共享组件定义，所以不会按实例数量直接乘算大小。
- **不同定义合计**：每个定义独立导出的文件大小之和。不同文件中可能重复包含共享的嵌套组件、材质及文件头，所以它不是“合并后精确体积”，也不表示删除这些对象后原模型会减小多少。
- **整个模型**：默认读取原 SKP 在磁盘上的大小，明确标记未保存修改；点击按钮后通过 `Model#save_copy` 测量当前模型副本。不会覆盖原 SKP。
- **散线、面和图片等**：没有独立的组件 SKP 文件。请先手动创建群组或组件再测量；混合选择时只显示可测定义明细，不显示误导性的完整合计。
- **单位**：1 KB = 1024 字节，1 MB = 1024 KB。显示的是文件体积，与内存占用及模型的长宽高不同。

临时副本在测量结束或失败后自动清理。插件不会自动清理模型、重组几何、让组件唯一化、覆盖原文件或更改组件源路径。SketchUp 官方文档记录了 2027 以前保存组件副本可能更新定义 GUID 的问题；依赖 GUID 做外部追踪的工作流应留意这一宿主程序行为。

面板是可移动、可缩放的独立窗口，不属于默认托盘中的原生“图元信息”面板。

## 验证情况

已使用 SketchUp 2026 随附的 Ruby 3.2.2 通过源码语法检查和 94 项隔离逻辑检查，并使用 Node 通过 51 项面板检查。独立浏览器还回放了 Ruby 面板实际生成的消息，验证按需展开、大小增量、定位回调和 440 / 320 像素布局。这些检查使用 SketchUp 对象的测试替身，不能替代 SketchUp 内真实模型的导出、原生事件、定位和速度验证，详见 [验证记录](TEST_RESULTS.md)。

性能回归场景在一个根群组内放置 3700 个不同定义，禁止枚举全局定义列表及调用 `definition.instances`：首次仅读取根级，展开后也不进入这 3700 个子定义。另检查宽层级停止/恢复、批量测量、去重、失败重试、增量传输、缓存复用、页面重新加载及对象路径校验。

## 源码结构

```text
src/
  model_size_info.rb              扩展注册入口
  model_size_info/
    main.rb                      菜单入口
    analyzer.rb                  定义去重、文件测量和缓存
    component_tree.rb            按需层级读取、共享缓存与对象路径验证
    panel.rb                     面板、监听和测量队列
    ui/
      panel.html
      panel.css
      panel.js
      tree.js                    按需展开、排序与分页
tests/
  logic_test.rb
  tree_test.rb
  ui_test.cjs
```

使用可用的 Ruby 2.7+ 执行 `ruby tests/tree_test.rb`（42 项原有检查和 52 项组件树检查）；使用 Node 执行 `node tests/ui_test.cjs`。插件不依赖第三方 Ruby gem、网络服务或账号。

重新打包：在项目根目录执行 `python build.py --output-dir dist`，即可生成安装包和源码包。也可以将 `src/` 里面的 `model_size_info.rb` 与同名文件夹放在 ZIP 根目录，再将扩展名改为 `.rbz`；不要把 `src/` 文件夹本身作为压缩包最外层。
